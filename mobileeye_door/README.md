# MobileEyeDoor Bridge

Превращает **видеодомофон CTV / XiongMai** — из тех, что работают только с
приложениями *MobileEyeDoor+* / *uCareHome* (например **CTV-M4101AHD**) — в
обычные RTSP/WebRTC-камеры внутри Home Assistant.

У этих домофонов **нет ни RTSP, ни ONVIF**. Видео отдаётся только по закрытому
двоичному протоколу XiongMai на «мобильном» порту (по умолчанию **10510**), на
котором говорят фирменные приложения. Дополнение общается с домофоном на его
языке, вытаскивает поток H.264 и заново публикует его через встроенный
[go2rtc](https://github.com/AlexxIT/go2rtc) — так каждый канал становится
обычной сущностью-камерой.

## Поддерживаемые устройства

Любой домофон/монитор на платформе XiongMai, чьё приложение —
**MobileEyeDoor+** или **uCareHome**, с открытым мобильным портом (8000 —
управление, 8090 — веб, 10510 — мобильный). Проверено на CTV-M4101AHD
(4-канальный AHD-монитор). Протокол одинаков для всей линейки, различается
только секрет входа.

## Как это работает

Клиент шлёт один **88-байтный кадр входа**, и домофон сразу начинает отдавать
H.264 для запрошенного канала — вход *и есть* запрос потока. Камеру выбирает
единственный байт кадра:

| байт 80 | камера |
|---------|--------|
| `0x01`  | 1      |
| `0x02`  | 2      |
| `0x04`  | 3      |
| `0x08`  | 4      |

Всё остальное в кадре (имя пользователя, хеш пароля, константы протокола)
зависит от устройства и задаётся один раз опцией `login_hex`.

## Как получить `login_hex`

Хеш пароля нельзя восстановить из обычного пароля — алгоритм хеширования
XiongMai не опубликован. Поэтому кадр входа, который ваше приложение и так
отправляет, перехватывается **один раз**:

1. Запустите приложение домофона, снимая его трафик к IP домофона:
   - **Android / эмулятор (BlueStacks):** встроенный `pktmon` в Windows
     справляется без Wireshark:
     ```
     pktmon filter add -i <IP_ДОМОФОНА>
     pktmon start --capture --pkt-size 0 --file-name cap.etl
     # откройте все камеры в приложении, затем:
     pktmon stop
     pktmon etl2pcap cap.etl -o cap.pcapng
     ```
   - **Телефон:** снимите трафик через PCAPdroid или зеркалированием на
     роутере.
2. Достаньте 88-байтный кадр входа из дампа:
   ```
   python3 tools/extract_login.py cap.pcapng
   ```
   Выведет строку `login_hex` (байт канала нормализуется).
3. Вставьте этот hex в опцию `login_hex` дополнения.

> `login_hex` содержит хеш пароля вашего домофона. Обращайтесь с ним как с
> секретом — он остаётся в конфигурации вашего Home Assistant, никуда его не
> публикуйте.

## Настройка

```yaml
host: 192.168.1.50          # IP домофона (закрепите за ним резервацию DHCP)
port: 10510                 # мобильный порт
login_hex: "0000005401..."  # 88-байтный кадр входа в hex (см. выше)
webrtc_ip: 192.168.1.10     # IP хоста Home Assistant, для WebRTC (необязательно)
cameras:
  - channel: 1
    name: door
  - channel: 3
    name: yard
```

Каждая запись становится потоком go2rtc с именем из `name`.

`webrtc_ip` включает WebRTC с задержкой меньше секунды. go2rtc внутри
дополнения видит только свой адрес в контейнере, до которого браузеру не
достучаться, поэтому адрес хоста нужно задать вручную — дополнение объявит его
как ICE-кандидат на порту `8555`. Если оставить пустым, плееры используют MSE
(тоже быстрее HLS, но с чуть большей задержкой).

## Как пользоваться камерами

После запуска дополнения потоки доступны по адресу:

```
rtsp://<home-assistant>:8554/<name>
```

Добавьте их в Home Assistant через **Настройки → Устройства и службы →
go2rtc**, либо интеграцией *Generic Camera* с этим RTSP-адресом, либо в
веб-интерфейсе go2rtc на порту `1984`.

## Ограничения

- **Мало одновременных подключений.** Домофоны XiongMai держат считаные
  сокеты. Если запустить это дополнение *и* приложение на телефоне на одну
  камеру одновременно, одному из них слота может не хватить. Отдавайте камеру
  одному потребителю.
- **Панели в режиме ожидания тёмные.** Вызывная панель у двери подсвечивается
  только при вызове; до этого её канал — чёрный кадр (поток рабочий, просто
  нет подсветки).
- Поток — какой кодирует домофон, обычно H.264 Baseline 640×480.
